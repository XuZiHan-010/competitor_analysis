# Recurring Feedback

## 语言与表达

- 默认中文回答。
- 解释要面向实际接手者，不要只给抽象概念。
- 面试、答辩、学习材料要能帮助零基础新人理解全栈项目。

## Plan 与文件位置

- 方案、计划、任务拆解统一放在 `plans/`。
- 不要把 plan 写到全局目录或项目外部。
- 若用户要求执行方案，先确认是否需要落文件；执行后说明路径。

## GitHub 与提交

- 用户没有明确要求时，不主动 commit、push 或创建 PR。
- 用户说 commit 时，含义是通过 GitHub PR 流程提交到远程，不只是本地提交。
- 提交前必须显式检查 staged diff，不能粗暴添加所有文件。

## 学习与交接材料

- 学习计划要覆盖 Agent、后端、前端、测试评估、部署上线和未来迭代。
- 目标读者是完全零基础的新员工，要从业务流程讲到代码入口。
- 只列文件名不够，必须说明每一层解决什么问题、上下游怎么通信、失败如何处理。

## 安全红线

- 不外泄真实密钥、平台凭据或生产服务访问材料。
- 不把敏感值写进文档、截图、聊天、Issue 或 PR 描述。
- 涉及上线和部署时，只写变量名和配置位置，不写真实值。
